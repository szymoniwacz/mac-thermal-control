## Proposed telemetry allowlist

Expose fixed typed operations, never a caller-supplied sysctl name, Mach flavor, driver selector, executable or argument vector. Native functions stay inside the collector worker. Source IDs below are proposed provenance identifiers, not implemented adapters. SDK/OS/framework internals are dependencies, not a proven sandbox; call review and fixture traces must verify the product's reachable operations.

### Inventory, once before sampling

For each listed selector, the only permitted form is `sysctlbyname(fixedName, fixedBuffer, &length, NULL, 0)`. The null new-value pointer and zero new length are mandatory even for writable selectors. Use bounded initialized storage, inspect return status and returned length before decoding, and never accept partial data after `ENOMEM`. Do not probe arbitrary MIBs, grow allocations from unchecked lengths or invoke the `sysctl` executable. Apple's API contract distinguishes retrieval from setting through those arguments; the source's `kern.osversion` handler has a write path, so a familiar key alone is not proof of read-only use.

| Selector / source ID suffix under `public.sysctl.*.v1` | Output | Proposed storage/type checks |
|---|---|---|
| `hw.model` / `model` | Model identifier | At most 128 bytes including terminator |
| `hw.machine` / `machine` | Reported architecture string | At most 128 bytes including terminator; no inference of support for another architecture |
| `machdep.cpu.brand_string` / `cpu_brand` | CPU model text | At most 256 bytes including terminator; no live-frequency interpretation |
| `kern.osversion` / `os_build` | OS build string | At most 256 bytes including terminator; no setter arguments |
| `hw.memsize` / `memory` | Physical bytes | Exactly SDK `uint64_t` width; positive; preserve integer precision |
| `hw.logicalcpu` / `logical_cpu_count` | Logical CPUs available in the reported power-management configuration | Exactly SDK `int` width; positive; not a permanent maximum |
| `hw.physicalcpu` / `physical_cpu_count` | Physical CPUs available in that configuration | Exactly SDK `int` width; positive; not a sampled utilization measure |

For strings require a successful nonzero length within the buffer, one trailing NUL, no embedded NUL, valid printable ASCII and nonempty content after bounded whitespace trimming. Reject malformed representations instead of retaining a raw dump. These are proposed software bounds, not hardware limits. Numeric widths are checked at the native boundary; convert through aligned typed storage, not unchecked pointer casts. Do not coerce counts/bytes through floating point or invent a value on failure. The reads are separate observations, not an atomic inventory snapshot.

Use only `ProcessInfo.processInfo.operatingSystemVersion` for OS major/minor/patch (`public.foundation.os_version.v1`), with three nonnegative bounded integers. Do not read `hostName`, `environment`, arguments, process lists, account details or free-form version descriptions. Persist only the reviewed fields, status, timestamp and provenance through a future approved inventory serializer. Existing `ObservationValue.number(Double)` is not an exact arbitrary-UInt64 inventory container; typed inventory encoding needs its own regression coverage.

For power context, inspect only dictionary keys `kIOPSTypeKey`, `kIOPSIsPresentKey` and `kIOPSPowerSourceStateKey`. Require the documented CFString/CFBoolean types before use; select present `kIOPSInternalBatteryType` entries. Inspect only fixed constants, not names/serials/capacity/history/registry data. All selected entries must agree: `kIOPSACPowerValue` maps to `ac`, `kIOPSBatteryPowerValue` to `battery`. Here `ac` means the battery reports an external supply, not proof of wall power or absence of a UPS. No eligible present battery or absent fields means `missing`; conflicting/offline/unknown state means `unverified`; wrong types or an over-limit list means `invalid`. These gaps carry null, with unknown context stated explicitly; they never become AC or zero. A known non-internal source is ignored, not relabeled as the laptop's battery.

**Exclude `IOPSGetProvidingPowerSourceType`.** In the pinned implementation it ignores its snapshot argument and defaults to AC after a failed supporting lookup. The snapshot-copy implementation can also turn failure into an empty list. Therefore neither the convenience result nor an empty list proves a successful AC observation or a genuinely battery-free machine. The selected description path retains the empty-list ambiguity as `missing`; it cannot authenticate the underlying hardware or guarantee freshness. Handle/list limits bound product decoding and IPC, not allocations performed internally by the OS framework; combined memory must still be measured. These are source findings, not observed target behavior.

### Status and failure mapping

Read attempts carry source identity and a check timestamp; success records the application's read time, not an exact hidden kernel measurement time. Store bounded typed reason codes, never `strerror`, exception descriptions, arguments, paths, dictionaries or raw IPC as report diagnostics. For sysctl, `EACCES`/`EPERM` map to `permission_denied`, `ENOENT`/`ENOTSUP` to `unsupported`, wrong widths/types/oversize to `invalid`, and other failures to `error`. A missing field in an otherwise valid power response is `missing`. Mach failures map to `error` unless an explicitly reviewed denial code establishes permission denial; do not infer privilege needs from an arbitrary return code. Unsupported capabilities never trigger elevation or a different source.

Use one `SourceFailurePolicy` per source/session (including individual inventory selectors). Timeout/denial disables immediately; malformed/error outcomes use its existing consecutive-failure budget. Inventory is attempted once; permission to retry is not a requirement to retry it. Valid responses with missing/unverified fields are transport successes with explicit observation gaps, not fabricated measurements or malformed IPC. A confirmed unsupported source is excluded from future attempts for that session by capability state; the current failure-policy enum alone does not implement this exclusion. Keep these responsibilities explicit when wiring code.

The pinned Mach implementation aggregates processors and can cache/rate-limit statistics. Zero total counter delta is insufficient data, not proof of idle; zero busy delta with advancing idle ticks is valid 0% activity. Feed successful ticks and measured elapsed time to `CPUActivityDelta`; first sample, reset/wrap, nonpositive/overlong interval and zero-total delta produce gaps. Reset baselines after sleep-like gaps, skipped frames, CPU-source failure or unavailable/disabled CPU state; no trend may bridge an unobserved interval. Tick activity is neither throughput nor operating frequency, power or proof of thermal throttling. Preserve possible cache/sampling latency in provenance.

## Proposed worker and parent contract

This is the D-020 adopted design for R-001 isolation, subject to implementation review and fixture validation. It is process fault isolation, **not an OS security sandbox or an authentication mechanism**. A child normally shares the user's permissions; privacy minimization depends on restricted code paths and response validation. No root, entitlement, service installation, network path, external telemetry executable or arbitrary command mode is proposed.

Prefer one reusable unprivileged worker, serial requests and a parent-owned process registry capped at **one not-yet-reaped worker**, including one in shutdown. This limits accumulation and memory overhead; actual combined CPU/RSS budgets remain unmeasured. Use fixed worker mode in the same reviewed executable via `posix_spawn` without shell/PATH lookup, with explicitly inherited protocol descriptors and no persisted environment dump. Close unrelated descriptors. Proposed lifecycle primitives are pipe setup, nonblocking `read`/`write`, `close`, timers, `kill` of the exact owned child PID, and `waitpid(..., WNOHANG)`. No synchronous `waitUntilExit`, blocking pipe read or indefinite reaper join is allowed on the parent control path. Exact process/descriptor APIs and PID lifecycle must be audited with the implementation.

1. Initialize inventory before establishing the sampling origin. Proposed initialization cap: 4 seconds total, at most one attempt for each of the eight inventory operations. Start no second worker until the previous child is confirmed reaped. A timeout cannot cause an immediate retry of the same source. An unreaped child stops initialization with an infrastructure failure, not partial silent continuation.
2. Give each request protocol version, fresh session ID, monotonically increasing request ID, fixed source enum and slot ID (inventory uses its separate phase). Proposed request maximum: 1 KiB; response maximum: 16 KiB including framing, both below R-001's 64 KiB record ceiling. Use one length-prefixed message; check the length before allocation and cap bytes while reading. No raw JSON/source dump on stderr; use a bounded diagnostic code channel or discard child stderr without accumulating it.
3. Worker returns exactly the requested typed payload or typed failure, echoed IDs and bounded read-start/read-end timing. It performs no scheduling, filesystem reporting or retry. Parent validates protocol/session/request/source/slot, lengths, allowed fields, finite ordered timestamps and payload types/ranges before accepting an observation. Duplicate, unknown, mismatched, unsolicited or late replies cannot satisfy a new request or revive a disabled source; invalid IPC retires the worker. EOF/crash is explicit failure. This requires a new strict decoder; `SessionReader` validates stored envelopes only and is unsuitable as this decoder.
4. Parent uses sleep-inclusive `mach_continuous_time()` and checked `mach_timebase_info` conversion for session-relative elapsed time. Require successful conversion, nonzero denominator and finite nondecreasing results. Wall time is recorded separately near each read; wall-clock adjustments never reorder monotonic elapsed time. Source timestamps describe application observation/check timing and retained uncertainty, not a guaranteed fresh kernel snapshot.
5. Drive starts through `SamplingSchedule`; there is one frame and one source request in flight at most. CPU, thermal and power operations run serially. The frame collection deadline is the earlier of actual frame start + 900 ms and configured session end. Per-source request budget is at most 500 ms including dispatch/startup. Reserve a proposed 200 ms shutdown allowance: do not start a request unless its full 500 ms budget plus that allowance fits before the frame collection deadline. If insufficient budget remains, emit `frame_budget_exhausted` gaps for unattempted sources, without falsely applying source-timeout penalties. Prioritize those skipped sources in the next slot to avoid starvation; never catch up skipped frames. Startup/dispatch costs count, not just the native function's time. Reject responses arriving after the frame collection deadline even if their source timer has not expired. At configured session end no native request may start or be accepted: a final logical slot yielded by `SamplingSchedule` exactly at duration contains explicit unattempted-source gaps, then releases its token; it grants no collection grace period. A poll after duration reports skipped slots rather than inventing frames.
6. On source timeout, mark that source disabled through its policy, ignore subsequent replies and shut down the worker; attempt other enabled sources only at a later scheduled frame after reaping. Proposed shutdown allowance: request/TERM, at most 100 ms grace, KILL if still alive, then nonblocking reaping for at most another 100 ms. These are parent wait limits, not a guarantee that a signal cancels synchronous kernel work. Do not respawn an unreaped worker or signal a PID after its ownership has been cleared/reaped. Failure to establish exit by the bound stops the session with `worker_exit_unconfirmed`, incomplete status and explicit uncertainty.
7. On cancellation or session end, stop scheduling native requests first, reject late results, preserve completed records and request bounded shutdown. Final session-level cleanup may run for at most the proposed 200 ms after the collection end/cancellation; it permits no further observations. Record the actual shutdown/end timing and any unconfirmed exit rather than presenting cleanup as extra collection time. Worker idle-loop EOF should trigger exit; test parent disappearance as well. A blocked child may outlive a dead parent: before any later capture, unresolved termination must be reconciled by the owner, never hidden through automatic replacements. This is not controller recovery or proof of independent Apple-auto restoration; no fan control exists here.

A source-local gap/denial/unsupported result does not automatically make the entire session an infrastructure failure. A broken/uninspectable worker lifecycle, protocol failure that cannot safely recover, or unwritable report does. Future integration must emit `source_error`, skipped-slot gaps and truthful `session_end` fields/exit status under R-001. `SamplingSchedule.complete` only releases a token; it proves neither worker exit nor report persistence. Its terminal `inFlightSlot` must not be interpreted as cancellation success. The future persistence path must independently enforce new-directory/symlink/permission/size/queue/end-record rules and bound its own waits; collector isolation does not solve filesystem blocking.
